# MyVCS 正式性能实验脚本说明

## 当前阶段

四组预实验已经完成并备份。正式实验采用新的毫秒计时工具，旧数据单独保留。
先运行四种场景各一轮的流程检查（formal-smoke01），确认后再运行正式的 20 轮。
流程检查不计入正式 20 轮。所有实验由用户在 openEuler 中启动。

## 文件

- `measure_command.py`：每次测量一条命令；结果 JSON 和输出日志使用独占创建，不覆盖旧文件。
- `run_reproduction.py`：准备输入、建仓、逐阶段计时、存储统计、验证、历史恢复核对及汇总。

两个 Python 文件应放在 openEuler 的同一个目录，例如 `/home/oslab/`。
只依赖 Python 标准库、已安装的 Git、GNU time 和已编译的 MyVCS。

## 固定实验口径

| 场景 | 文件大小 | 增量次数 | 每次覆盖长度 | 偏移 |
|---|---:|---:|---:|---|
| random20 / ab20 | 20 MiB | 5 | 4 KiB | 1、2、3、4、5 MiB |
| random128 / ab128 | 128 MiB | 2 | 64 KiB | 1、2 MiB |

- 使用已保存的预实验输入和补丁；同规模随机/A/B 场景复用同一补丁序列。20 轮复用固定数据，每轮新建仓库，是固定工作负载的重复测量。
- 检查 MyVCS 二进制是否与已记录的预实验 SHA-256 相同，不改项目源码或优化开关。
- 清除子进程继承的 `MYVCS_*` 参数，采用默认行为，包括负载感知 GC 策略。
- Git 禁用全局/系统配置和初始化模板，设置本地身份、关闭提交签名和自动 GC；使用普通 `git gc`。这是显式控制配置的正式实验口径，与预实验可能继承的用户配置有区别。
- 奇数轮 MyVCS 先执行，偶数轮 Git 先执行；每轮轮换场景顺序。两个工具顺序运行，不并发竞争 CPU。
- 不清理 Linux 页缓存；复制和哈希检查会预热文件页面。新建仓库不能保证冷缓存。本实验应报告为未清空缓存、输入预热条件下的测试。
- `elapsed_ms` 是 Python 高分辨率时钟围绕 GNU time 和目标命令记录的时间，包括启动 GNU time 的开销；不减去帮助命令或 sleep 自检的耗时。
- 目标命令的标准输出和错误输出写入日志，正式实验两工具一致采用此方式。
- RSS 使用 Linux GNU time `%M` 的峰值 KiB。分别报告提交流程、GC、验证，不能用 add 的低内存代表整个程序。
- 存储量累计对象目录中的文件字节数，包含 Git pack、索引等文件，不包含工作区文件或文件系统分配块开销。
- 空间节省率分母为数据版本数 × 文件大小；20 MiB 组为 120 MiB，128 MiB 组为 384 MiB。
- 每个版本的 add 和 commit 分别计时，总耗时为两者之和。每轮先对增量版本求均值，再对 20 轮的均值做统计；不会把同一轮的多个版本当作独立轮次。
- 每次测量前后保存 `/proc/loadavg`、`meminfo`、`vmstat`，用于诊断系统状态；这些快照不证明测量期间从未换页。
- 如果 MyVCS 因负载跳过增量 GC，停止并保留记录，不强制覆盖策略，不自动丢弃样本重试。需要检查后再决定如何处理未完成实验。

## 正确性和清理

每轮对两工具执行完整性检查，并在 GC 后逐个 checkout 所有数据版本，核对 SHA-256，最后回到 main。历史恢复检查不计入提交、GC 或验证的性能数字。

只有上述步骤全部成功的临时仓库才删除。删除范围限制在本次运行目录的直接子目录，要求名称和所有权标记匹配，并拒绝符号链接。预实验目录和源项目不属于清理范围。
失败的临时仓库、全部日志和结果保留；不支持原地恢复或同名覆盖。

## 当前执行步骤

```bash
python3 ~/run_reproduction.py --check --run-name formal-smoke01 --rounds 1
python3 ~/run_reproduction.py --run-name formal-smoke01 --rounds 1
```

第一条只检查输入、二进制、工具、空闲空间和目标目录，不运行实验。
检查通过后才执行第二条。过程中保持电脑唤醒、VMware 和 SSH 连接正常，避免其他重负载任务。

输出位置：

- 结果和日志：`~/os-lab/repro-results/formal-smoke01/`
- 固定输入副本和可能保留的失败现场：`~/os-lab/benchmarks/formal-smoke01/`
- `results.csv`：每个工具每轮每场景一行；流程检查应为 8 行数据。
- `aggregate.json`：每场景每工具的均值、中位数、样本标准差、最小值和最大值；只有一轮时标准差为 null。
- `completed.json`：只在全部场景完成后生成；应为 4 个场景轮次、8 个工具轮次。
- `manifest.json`：输入哈希、环境信息及方法；另存运行脚本、Cargo 文件和源码副本。

流程检查确认后，再使用一个全新的运行名和 `--rounds 20`，不把 formal-smoke01 合入正式结果。

## 结论边界

当前是 VMware 中的 openEuler；硬件、虚拟化和工具链与论文不完全相同。论文未提供的补丁内容、偏移和计时细节采用上述明确约定。
20 轮用于描述固定环境中的运行波动；不能仅凭最大 RSS 低或单轮成功证明没有内存泄漏，也不能将单个快操作的更多小数位解释为等量准确度。
