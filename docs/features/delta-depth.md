# F04：限制新建 GC Delta 链

本轮调整本地 GC 存储编码，不改变逻辑 OID、提交树或远程 pack 协议。

- 默认合法旧对象读取预算仍为 64 个节点。
- GC 新生成链最多 **8 个节点，包含完整基础对象**，即完整对象深度为 1、最多 7 条 delta 边。
- 旧有合法深链不强行重写/截断；因此升级后 stats 的最大深度可能仍大于 8。
- 以祖先先于后代的顺序处理提交。只考虑首父提交同路径基础；候选不合适时保留完整对象，不进行全库最优基础搜索。
- 预扫描并保留已有 delta 的基础对象，禁止把它们改写成更深的链。重复 GC 不应使间接依赖突破新链阈值。
- 沿用实际压缩收益门槛：新对象压缩字节数加 16 仍须小于旧存储大小。保留对象/操作数/链预算检查，写入前重建并核对 SHA-256，使用原子对象替换。

已有负载策略可跳过深度优化；测量脚本使用 `MYVCS_FORCE_DEEP_DELTA=1` 固定实验条件。GC 仍保护分支、远端引用、标签、stash/pins、reflog、合并状态、FETCH_HEAD、暂存对象与物理 delta 基础。

```bash
MYVCS_FORCE_DEEP_DELTA=1 myvcs gc
myvcs verify
myvcs stats --json
```

正确性和性能分开验收：最大深度约束、旧 16 节点链读取、坏/缺失基础失败、重复 GC 与全部历史还原均有测试；实际存储、时间和峰值 RSS 详见 [性能报告](../benchmark.md)。没有普遍加速或降低峰值内存的结论，也未实现自动缩短所有旧链。
