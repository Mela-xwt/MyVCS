# P1 架构与一致性边界

CLI 位于 `src/cli.rs`，分派在 `src/main.rs`。Repo 实现复用已有安全路径检查、仓库锁、原子文件写入、对象 SHA-256、引用状态事务与 GC 根遍历。

```text
status / add / stash -u --> ignore.rs --> 根目录规则与统一扫描
restore / stash -------> restore.rs --> 保护 pin --> journal --> 文件/索引
                                      |                  |
                                      +-- GC 可达根 -----+--> recover-worktree
stash.rs --> 合成提交 + refs/pins/stash --> 既有 GC / verify
GC --> 祖先优先候选 + 基础保留 + 新链上限 8 --> 完整对象回退
stats --> 既有 GC 保护根 + 对象库枚举
 doctor --> 系统只读探测 + 既有 I/O 配置
```

工作区事务在写入前读取两侧 Blob、做覆盖预检并保存两侧状态。快照与恢复 pin 使用既有引用机制；格式 2 引用事务保证单次状态发布。多文件工作区更新采用逐文件原子替换加 journal 的可恢复模型，并不承诺任意时刻外部编辑器都只能看到整个操作的最终状态。仓库锁约束合作的 MyVCS 进程，无法阻止其他程序同时写文件。

正常命令通过仓库锁检查未完成 journal；恢复入口绕过该检查，在锁内校验 HEAD、索引、路径与文件内容。新编辑既不等于 before 也不等于 after 时拒绝覆盖。先删除 journal、后删除恢复 pin，使崩溃窗口优先保留对象，代价是可能残留孤立 pin。

索引、stash 元数据与 journal 有边界检查；对象格式与哈希兼容当前阶段 3，无新增仓库格式号。真实权限隔离仍依赖服务端受限 SSH 入口及可信身份映射；提交作者不是权限凭证。
