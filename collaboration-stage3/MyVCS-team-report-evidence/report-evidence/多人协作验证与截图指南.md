# MyVCS 多人协作：报告验证指南

整理日期：2026-10-23。本文引用工作区已完成的真实验收记录；本轮整理没有重新执行服务器验收。PNG 是真实日志摘录页面的浏览器截图，不是重新运行的终端截图。原始日志、行号及 SHA-256 见 `manifest.json`。若课程要求实时终端截图，按下面命令重新运行即可。

## 1. 报告怎么组织

不要只放“cargo test 全绿”。建议以“操作 → 观察结果 → 断言 → 结论”组织证据：

| 用例 | 命令/触发 | 应观察什么 | 报告图 |
| --- | --- | --- | --- |
| A/B 同步 | A commit/push，B clone | 双方相同完整提交 OID；文件字节比较见第 4 节 | 01-sync.png |
| 过期推送与合并 | A 先 push，B 独立提交后 push/pull | B 被拒绝；pull 生成含两个父 OID 的提交 | 02-merge.png |
| 身份与分支权限 | reader 伪造作者；Bob 推送禁止分支 | 读取或写入被拒绝；原子批次不改变任一引用 | 03-policy.png |
| lease 与并发 | 过期/正确 lease；两进程同时推送两个引用 | 过期 lease 拒绝；一成一败；两个引用都指向胜方提交 | 04-lease-race.png |
| GC 后恢复 | 改写分支、删旧标签、GC、recover | 旧提交仍可从 reflog 恢复，新建 rescued 分支，verify 成功 | 05-recovery.png |
| 手动冲突与 abort | 专项测试或下方手工演示 | abort 恢复开始状态；手动解决提交保留两父 | 现场截取专项测试/终端 |

日志中的 `actor=alice`、`exit=0` 是验收脚本打印的说明，不是 MyVCS 命令参数。实际身份由独立 SSH 密钥对应的 forced command 绑定，不能通过命令行伪造。

## 2. 最简单的真实 SSH 复现（推荐截图方式）

Windows PowerShell：

```powershell
cd D:\DOWNLOAD\OperatingSystems\group_work
python collaboration-stage3/remote_validate.py --acceptance
```

交互输入服务器密码，不在截图中显示或写入报告。此命令使用 `server-directory.txt` 指向的已部署二进制，先逐文件检查服务器源码与本地源码一致，再在临时目录建立 A/B 等仓库、临时 SSH 服务与独立身份密钥。运行结束后退出测试 SSH 服务并清理测试私钥，不修改系统 authorized_keys。

若源码已变或部署目录不存在，先运行 `python collaboration-stage3/remote_validate.py` 重新隔离构建，再运行 `--acceptance`。这会更新已有验收日志；需要保留原报告依据时先复制日志。旧日志中的临时端口已经关闭，不能直接复制 `39137` 端口继续 clone。

也可登录服务器直接运行，适合拍摄完整终端：

```bash
ssh oslab@192.168.220.129
cd /home/oslab/os-lab/myvcs-stage3.cmjI2y
set -o pipefail
python3 collaboration-stage3/ssh_acceptance.py \
  --bin "$PWD/target/release/myvcs" 2>&1 | tee /tmp/myvcs-team-report.log
echo "exit=$?"
```

末尾应出现（这是现有日志的真实输出）：

```text
verify ok: 6 commit(s), 6 blob reference(s), 12 reachable object(s)
PASS real SSH identities, line merge, atomic refs, tags, prune, explicit lease, GC/reflog recovery and audit
```

成功退出码应为 0。中间的 `EXPECTED: Error:` 是预期拒绝场景，不能当作整个验收失败。每次提交时间不同，OID、临时目录和端口会变化；比较的是当次运行中的相等关系，不是固定哈希常量。

建议终端宽度至少 140 列，字体 14～16，截图保留命令、关键输出和错误原因。使用 Win+Shift+S，按上述图名保存；不要把输入密码的画面纳入截图。

## 4. 手动冲突解决与 abort：可复制的本地演示

在 WSL Bash 中运行以下命令。此段是独立的可复现演示步骤，下面标注的是判定条件，不冒充已捕获输出。`file://` 使用真实子进程协议，但不能证明 SSH 身份隔离；SSH 权限使用第 2 节验证。

```bash
cd /mnt/d/DOWNLOAD/OperatingSystems/group_work
export PATH="$HOME/.cargo/bin:$PATH"
CARGO_TARGET_DIR=/tmp/myvcs-stage3-report-build cargo build --locked --offline
BIN=/tmp/myvcs-stage3-report-build/debug/myvcs
DEMO=$(mktemp -d /tmp/myvcs-report.XXXXXX)
cd "$DEMO"
"$BIN" init --bare --team server
"$BIN" clone "file://$DEMO/server" A
"$BIN" --repo A upgrade --quiescent
printf 'base\n' > A/shared.txt
"$BIN" --repo A add shared.txt
"$BIN" --repo A commit -m base
"$BIN" --repo A push
"$BIN" clone "file://$DEMO/server" B
"$BIN" --repo B upgrade --quiescent

# 同一行冲突：A 先推送，B 仍在旧历史上提交。
printf 'Alice\n' > A/shared.txt
"$BIN" --repo A add shared.txt
"$BIN" --repo A commit -m Alice
"$BIN" --repo A push
printf 'Bob\n' > B/shared.txt
"$BIN" --repo B add shared.txt
"$BIN" --repo B commit -m Bob
"$BIN" --repo B push       # 应拒绝 non-fast-forward
"$BIN" --repo B pull       # 进入冲突状态
cat B/shared.txt           # 截图：冲突标记
"$BIN" --repo B status

# 验证取消：恢复到 B 已提交的 Bob 内容。
"$BIN" --repo B merge --abort
cat B/shared.txt           # 应为 Bob
"$BIN" --repo B status

# 再次合并并手动解决。
"$BIN" --repo B pull
printf 'Alice + Bob\n' > B/shared.txt
"$BIN" --repo B add shared.txt
"$BIN" --repo B commit -m 'resolve conflict'
"$BIN" --repo B log --graph   # 截图：Parents 中有两个不同 OID
"$BIN" --repo B push
"$BIN" --repo A pull
cmp A/shared.txt B/shared.txt && echo 'PASS: A/B file bytes identical'
"$BIN" --repo A verify
"$BIN" --repo B verify
echo "演示目录：$DEMO"
```

报告判定：`cmp` 成功表明文件字节相同；DAG 的两个父 OID 表明双方历史均被保留；`verify` 用于检查引用可达历史和对象完整性。仅“文件看起来一样”不足以证明历史完整。

## 5. 故障与全量测试：补充证据

在 WSL 项目根目录执行：

```bash
export CARGO_TARGET_DIR=/tmp/myvcs-stage3-report-build
cargo test --locked --offline --test team_merge overlap_resolution_records_two_parents_and_abort_restores_exact_state -- --exact
cargo test --locked --offline --lib actual_process_loss_during_multi_receive_installs_or_publication
cargo test --locked --offline --lib delta_pack_rejects_missing_forward_cyclic_unconfirmed_corrupt_and_oversized_data

```

最后一个坏 delta 测试名称请以 `cargo test --locked --offline -- --list` 的实际列表为准；没有匹配的过滤器可能退出成功却运行 0 项，截图必须包含 `1 passed` 或实际非零用例数，不能只截退出码。

已有最终记录：`final-fix-tests.log` 先运行 15 项专项，再运行 131 项全量；不要把它加成 146 个不同测试。服务器 `server-build-tests.log` 的全量分组为 40+9+13+12+14+16+12+15=131，全部 0 failed。进程终止测试验证引用是全部旧或全部新，不是实际断电验证。

## 7. 可直接放入报告的总结

本实验通过两个独立客户端工作区模拟多人协作，并使用不同 SSH 密钥映射的服务端身份验证权限。结果表明，A 推送的提交可被 B 克隆/拉取；过期推送被拒绝；分叉合并保留双方父提交；多引用竞争只有一个事务成功，未出现部分更新；在 reflog 保留期内，GC 后仍可恢复被改写的历史。WSL 与 openEuler 各完成 131 项自动化测试，均无失败。SSH 多身份验收使用服务器回环高端口，不等同于本轮跨物理主机压力测试；原生 Windows 崩溃持久性、实际断电及 HTTPS 不在本轮验证范围。
